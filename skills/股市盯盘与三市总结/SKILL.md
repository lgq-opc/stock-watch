# 股市盯盘与三市总结

轻量、可复用。仓库路径、远程、作者名、观察名单文件由**调用方（例行任务或用户）**指定；本技能不写死某一用户或某一 org。

## 模式

调用方指定其一：

- **intraday**：盘中一波（开盘前 / 早盘 / 午休 / 午后）
- **daily-summary**：三市日终总结（通常在港股收盘后）

## 每次开跑必做

1. **读上下文**
   - 观察名单（默认 `config/watchlist.md`）：分清 Tier-1（必覆盖）与 Tier-2（异动才写）。
   - 若存在 `config/evolution.md`：先读「现行改进」与最近教训，本轮执行时遵守。
   - 若存在当日已有笔记：复用价格与事实，避免前后矛盾。

2. **休市判断**
   - 该波所覆盖市场若全部休市，且无必须告知的停牌/重大公告：在 notes 留一行「休市」，**不打扰用户**，仍可做一次极简 evolution 记录后结束。
   - 部分市场休市：只写开市部分，明确标注休市市场。

3. **取数（公开来源，不强依赖付费插件）**
   - 顺序：交易所/权威财经站公开报价 → 可靠新闻稿 → 公司公告。
   - 每个数字尽量带来源或页面；拿不到就写「未取到」，**禁止编造价格**。
   - 美股在亚洲午后：以「昨夜收盘」为主；若已开盘，单独标明盘前/盘中且标注时区。

4. **写作**
   - **intraday**：追加到当日分节笔记（调用方给定路径，常见 `notes/YYYY-MM-DD.md`），标题标明波次时刻。
   - **daily-summary**：写 `notes/YYYY-MM-DD-daily-summary.md`（或调用方路径）；提炼全日，不简单粘贴四波原文。
   - 结构建议：指数/大盘一句 → Tier-1 表或短列表（价、涨跌、区间）→ 高信号新闻（≤3）→ 相对强弱/风险一句。
   - 文末固定：「不是投资建议。」
   - 语言：调用方指定（默认简体中文、可扫读）。

5. **质量自检（发出去之前，必须过）**
   - [ ] Tier-1 无遗漏（休市除外）
   - [ ] 无编造数字；未知已标明
   - [ ] 涨跌方向与百分比未写反
   - [ ] 新闻归因未夸大成「已证实」的未证实传闻
   - [ ] 与当日早前笔记无自相矛盾
   - [ ] 已写「不是投资建议」
   - 任一项失败：先修正笔记再投递；修不了则向用户说明缺口，不要硬发完整报告。

6. **审阅门闩**
   - 默认：**先完成归档（commit/push 若调用方要求），再投递用户**。
   - 投递前用 3–6 句做「编辑审阅」：指出本波最硬的事实、最大不确定、是否建议改名单/改扫描节奏。
   - 若调用方要求「主助手审阅」：把完整稿与自检结果交给主会话助手，由其决定是否原文发送或改后再发；例行任务隔离跑时，则在**同一轮**内完成自检+审阅口吻后再发，并在 evolution 记「已自审」。

7. **归档**
   - 按调用方要求 commit + push；commit 说明写清模式与日期。

## 自进化（每轮结尾，轻量）

追加写入项目内 `config/evolution.md`（无则创建），保持简短：

```markdown
## YYYY-MM-DD HH:mm · {intraday|daily-summary}
- 有效：…
- 摩擦：…（取数失败、名单过长、时差混淆等）
- 下轮试行：…（一条即可）
```

规则：

- 每周最多把「下轮试行」里**已验证有效**的 1–2 条提升到文件顶部的「现行改进」清单。
- 「现行改进」超过约 8 条就合并/删过时条，避免膨胀。
- **不要**每轮改本技能正文；只有同一摩擦连续出现 ≥3 次，或用户明确要求时，才提议更新技能（说明改点，征得同意或由主助手写入）。
- 名单增减写 `watchlist`，不写进技能。

## 明确不做

- 不给出买卖点、仓位、荐股。
- 不把未上市标的写成股价。
- 不假装拥有实时券商行情权限。
